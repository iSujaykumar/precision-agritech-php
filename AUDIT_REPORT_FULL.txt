FINDINGS

F01 High FIXED
File: tests/catalog_rules.php (previously no guard) and dev-router.php / .htaccess.
Evidence: the built-in server served any existing PHP file, including tests/catalog_rules.php, which updates categories and products before rolling back.
Impact: a visitor could run the test against the shop database. A crash before rollback could leave a category hidden.
Fix: the test exits unless it is the command line. /tests/ and other text notes return 403.

F02 Medium FIXED
File: .htaccess, dev-router.php.
Evidence: only SETUP-NOTES.txt and UPLOAD.txt were denied. New audit notes would have been downloadable.
Impact: internal notes could leak.
Fix: every .txt file except /robots.txt is denied. robots.txt is still the dynamic robots file.

F03 Medium FIXED
File: database/upgrade.sql, includes/migrate.php, admin/migrate.php.
Evidence: upgrade.sql uses stored procedures. Some Hostinger plans block CREATE PROCEDURE in phpMyAdmin.
Impact: an old database could not be updated.
Fix: Desk → Settings → Database update runs the same file in PHP, without creating procedures. It only adds missing pieces. phpMyAdmin import of upgrade.sql remains the preferred path.

F04 Low FIXED
File: shop.php.
Evidence: sort was only name or price ascending. New and offer products could not be filtered.
Fix: Price low, Price high, New, and Offers chips. Offers uses the shared offer rule. Old sort=price links still work.

F05 Low FIXED
File: product.php, assets/css/site.css.
Evidence: product pages had no breadcrumb trail or BreadcrumbList data.
Fix: Home / Shop / category / product, plus JSON-LD. The product price in structured data is still the selling price, not a fake sale price.

F06 Low FIXED
File: admin/products.php.
Evidence: staff could not see which offers were live, scheduled, or expired without opening each product.
Fix: a one-line summary on the product list, using the same offer rule as the shop.

F07 Low FIXED
File: assets/css/site.css.
Evidence: cards moved on hover with no reduced-motion exception.
Fix: the hover motion is skipped when the browser asks for reduced motion.

F08 Medium NOT FIXED
File: account.php around the mobile update.
Evidence: a signed-in customer can save a new mobile number without a code.
Impact: they could put another unused number on their account. They do not gain that person's orders, because orders are matched by user id or a verified email, not by the new phone alone.
Reason left: a code step needs the SMS provider, which is not configured here. Do not change it until staging can send codes.

F09 Low NOT FIXED
File: auth/google-callback.php.
Evidence: if local certificate checks fail, the code asks Google's tokeninfo endpoint and still checks issuer, audience, expiry, nonce, and email_verified.
Reason left: this is a fallback, not the normal path. Removing it would break sign-in in this sandbox. Confirm it on staging with real Google credentials.

F10 Low NOT FIXED — intentional
File: cron.php.
Evidence: the cleanup URL carries the cron token as a query parameter.
Reason left: Hostinger cron calls a URL. The token is compared in constant time and a wrong token returns 404. Keep the token out of the repository.
