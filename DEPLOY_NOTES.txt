DEPLOY NOTES — Precision Agritech

PHP
- PHP 8.1 or newer. This copy was checked on PHP 8.3.32.
- Extensions: pdo_mysql, gd, fileinfo, curl, mbstring, openssl.
- The database may be MariaDB, MySQL 5.7, or MySQL 8. The SQL was written for all three. It was run on MariaDB 11.4.8 only.

config/config.local.php
Copy config/config.example.php to config/config.local.php on the server. Do not upload a copy from a developer machine. Fill these names only:
db_host, db_port, db_name, db_user, db_pass, site_url, mail_from,
twilio_sid, twilio_token, twilio_verify, sms_provider, msg91_authkey, msg91_template_id,
google_client_id, google_client_secret,
smtp_host, smtp_port, smtp_secure, smtp_user, smtp_pass,
cron_token, allow_setup, turnstile_site_key, turnstile_secret,
show_otp_on_screen, debug.

Production values
- allow_setup = false after the first staff account exists.
- debug = false.
- show_otp_on_screen = false.
- site_url = the real https address, with no slash at the end.
- cron_token = a long random string. Never commit it.

Upload
- Upload the site into the domain folder (public_html or the staging folder).
- Keep the existing config/config.local.php if one is already there.
- uploads/products and uploads/private must be writable by PHP. uploads/private must not be browsable. The included .htaccess files deny PHP and private files.
- Do not delete the products/ photos. Those are the seed tray pictures.

Database
Preferred: phpMyAdmin, import database/upgrade.sql, then import it again.
Fallback: nursery desk → Settings → Database update, twice.
Fresh empty database: import database/schema.sql once. You do not also need upgrade.sql after a fresh schema import, but running it afterwards should still succeed.

Backup
- phpMyAdmin → Export the database before every update.
- Download the uploads/ folder as well. Photos are not in the database.
- Keep both files until the new version has taken a real order successfully.

Rollback
- Put the previous files back, including the previous config.local.php.
- Import the database export you took before the update.
- This update does not delete columns, so leaving the new columns in place is also safe if you only roll the PHP files back.

Cron
Call this URL every 15 minutes:
https://YOUR-DOMAIN/cron.php?token=YOUR_CRON_TOKEN
A wrong token returns "Not found". A correct call releases expired unpaid reservations once.

After go-live
- Open /admin/health.
- Place one small real order and confirm the reservation, the payment instruction, and the customer email or the on-screen order link.
- Confirm /tests/ and /database/schema.sql do not open.

Database update for the 2026-27 lists
- XAMPP or Hostinger: import database/upgrade.sql in phpMyAdmin. If it stops on a procedure, use Desk → Database update instead. Run it twice. It only adds missing columns and tables.
- If the homepage says "We are updating the shop", the new columns are not there yet. Staff who are signed in see a link to the database update. The public page does not show the SQL error.
- After the update, open Desk → Price lists and press "Load the supplied 2026-27 and farmer sheets". Pressing it again does not duplicate varieties.
- Do not replace the live address or email. The PDF wording is only recorded in IMPORT_REPORT.txt.
